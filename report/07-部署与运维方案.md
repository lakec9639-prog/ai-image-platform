## 7.2 Docker Compose 部署

### docker-compose.yml

```yaml
version: '3.8'

services:
  # ── PostgreSQL ──
  postgres:
    image: postgres:15
    container_name: ai-image-postgres
    restart: unless-stopped
    environment:
      POSTGRES_DB: ai_image_db
      POSTGRES_USER: ${DB_USERNAME:-postgres}
      POSTGRES_PASSWORD: ${DB_PASSWORD:-postgres}
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data
      - ./init-db:/docker-entrypoint-initdb.d   # 初始化 SQL
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${DB_USERNAME:-postgres} -d ai_image_db"]
      interval: 10s
      timeout: 5s
      retries: 5

  # ── Redis ──
  redis:
    image: redis:7-alpine
    container_name: ai-image-redis
    restart: unless-stopped
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data
    command: redis-server --appendonly yes --requirepass ${REDIS_PASSWORD:-}
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 5s
      retries: 3

  # ── MinIO ──
  minio:
    image: minio/minio:latest
    container_name: ai-image-minio
    restart: unless-stopped
    ports:
      - "9000:9000"   # API
      - "9001:9001"   # Console
    environment:
      MINIO_ROOT_USER: ${MINIO_ACCESS_KEY:-minioadmin}
      MINIO_ROOT_PASSWORD: ${MINIO_SECRET_KEY:-minioadmin}
    volumes:
      - minio_data:/data
    command: server /data --console-address ":9001"
    healthcheck:
      test: ["CMD", "mc", "ready", "local"]
      interval: 30s
      timeout: 10s
      retries: 3

  init-buckets:
    image: minio/mc:latest
    container_name: ai-image-init-buckets
    depends_on:
      minio:
        condition: service_healthy
    entrypoint: >
      /bin/sh -c "
      sleep 2 &&
      mc alias set myminio http://minio:9000 ${MINIO_ACCESS_KEY:-minioadmin} ${MINIO_SECRET_KEY:-minioadmin} &&
      mc mb myminio/ai-text-image --ignore-existing &&
      mc mb myminio/ai-img2img-out --ignore-existing &&
      mc mb myminio/ai-source-img --ignore-existing &&
      echo '✅ MinIO buckets created'
      "

  # ── Spring Boot 后端 ──
  backend:
    build:
      context: ./backend
      dockerfile: Dockerfile
    image: ai-image-backend:latest
    container_name: ai-image-backend
    restart: unless-stopped
    ports:
      - "8080:8080"
    environment:
      # 数据库
      SPRING_DATASOURCE_URL: jdbc:postgresql://postgres:5432/ai_image_db
      SPRING_DATASOURCE_USERNAME: ${DB_USERNAME:-postgres}
      SPRING_DATASOURCE_PASSWORD: ${DB_PASSWORD:-postgres}
      # Redis
      SPRING_REDIS_HOST: redis
      SPRING_REDIS_PASSWORD: ${REDIS_PASSWORD:-}
      # MinIO
      MINIO_ENDPOINT: http://minio:9000
      MINIO_ACCESS_KEY: ${MINIO_ACCESS_KEY:-minioadmin}
      MINIO_SECRET_KEY: ${MINIO_SECRET_KEY:-minioadmin}
      # 豆包 API
      ARK_API_KEY: ${ARK_API_KEY}
      ARK_BASE_URL: https://ark.cn-beijing.volces.com/api/v3
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy
      minio:
        condition: service_healthy

  # ── Nginx ──
  nginx:
    image: nginx:1.25-alpine
    container_name: ai-image-nginx
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/nginx.conf
      - ./nginx/ssl:/etc/nginx/ssl          # SSL 证书目录（生产）
      - ./frontend/dist:/usr/share/nginx/html  # 前端静态文件
    depends_on:
      - backend

volumes:
  postgres_data:
  redis_data:
  minio_data:
```

## 7.4 Dockerfile（后端）

```dockerfile
# 构建阶段
FROM maven:3.8.8-eclipse-temurin-17 AS builder
WORKDIR /app
COPY pom.xml .
RUN mvn dependency:go-offline -B
COPY src ./src
RUN mvn package -DskipTests -B

# 运行阶段
FROM eclipse-temurin:17-jre-alpine
WORKDIR /app
COPY --from=builder /app/target/*.jar app.jar

# 时区
RUN apk add --no-cache tzdata \
    && cp /usr/share/zoneinfo/Asia/Shanghai /etc/localtime \
    && echo "Asia/Shanghai" > /etc/timezone

EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

## 7.5 Nginx 配置

```nginx
# nginx.conf
upstream backend {
    server backend:8080;
    keepalive 64;
}

server {
    listen 80;
    server_name ai-image.example.com;
    return 301 https://$server_name$request_uri;  # HTTP → HTTPS
}

server {
    listen 443 ssl http2;
    server_name ai-image.example.com;

    ssl_certificate     /etc/nginx/ssl/cert.pem;
    ssl_certificate_key /etc/nginx/ssl/key.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;

    # 前端静态资源
    root /usr/share/nginx/html;
    index index.html;

    # Gzip 压缩
    gzip on;
    gzip_types text/plain application/json image/png image/jpeg;
    gzip_min_length 1024;

    # API 反向代理
    location /api/ {
        proxy_pass http://backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 超时设置（豆包 API 响应可能较慢）
        proxy_connect_timeout 10s;
        proxy_read_timeout    120s;
        proxy_send_timeout    30s;
    }

    # 前端 SPA 路由（所有非 API 请求返回 index.html）
    location / {
        try_files $uri $uri/ /index.html;
        expires 7d;
        add_header Cache-Control "public, immutable";
    }

    # 禁止访问敏感文件
    location ~ /\.env|\.git|\.dockerignore {
        deny all;
        return 404;
    }
}
```

## 7.6 健康检查与监控

### 7.6.1 健康检查端点

Spring Boot Actuator 提供以下端点：

| 端点 | 路径 | 说明 |
|------|------|------|
| 健康检查 | `/actuator/health` | 返回数据库、Redis 等连接状态 |
| 指标 | `/actuator/metrics` | JVM 内存、线程、GC 等 |
| 日志级别 | `/actuator/loggers` | 动态调整日志级别 |
| 信息 | `/actuator/info` | 应用版本、构建信息 |

```xml
<!-- pom.xml 中引入 Actuator -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>
```

```yaml
# application.yml
management:
  endpoints:
    web:
      exposure:
        include: health,metrics,info
  endpoint:
    health:
      show-details: when-authorized
```

## 7.7 启动与部署步骤

### 7.7.1 首次部署

```bash
# 1. 克隆代码
git clone <项目地址> && cd ai-image-platform

# 2. 配置环境变量
cp .env.example .env
# 编辑 .env，填入真实的密钥

# 3. 构建后端
cd backend && mvn clean package -DskipTests && cd ..

# 4. 构建前端
cd frontend && npm install && npm run build && cd ..

# 5. 启动全部服务
docker compose up -d

# 6. 查看日志确认启动成功
docker compose logs -f
```

### 7.7.2 日常操作命令

```bash
# 查看所有服务状态
docker compose ps

# 启动/停止/重启
docker compose start
docker compose stop
docker compose restart backend

# 更新后端代码后重新部署
docker compose build backend
docker compose up -d backend

# 查看资源占用
docker stats
```

### 7.7.3 预期启动时间

| 服务 | 启动时间 | 备注 |
|------|---------|------|
| PostgreSQL | 10-20s | 首次初始化表 |
| Redis | 2-5s | |
| MinIO | 3-5s | |
| init-buckets | 1s | 依赖 MinIO 就绪后瞬间完成 |
| Spring Boot | 15-30s | 依赖前三个就绪后 |
| Nginx | 1-2s | |

**完整启动顺序**：PostgreSQL → Redis → MinIO → init-buckets → Backend → Nginx

**全部就绪预计**：约 40-60s

## 7.8 数据备份与恢复

### 7.8.1 PostgreSQL 备份

```bash
# 每日备份脚本 (backup-pg.sh)
#!/bin/bash
BACKUP_DIR="/backup/postgres"
DATE=$(date +%Y%m%d_%H%M%S)
DB_NAME="ai_image_db"
DB_USER="postgres"

docker exec ai-image-postgres pg_dump -U $DB_USER $DB_NAME \
  | gzip > "$BACKUP_DIR/${DB_NAME}_${DATE}.sql.gz"

# 保留最近 7 天，删除旧备份
find $BACKUP_DIR -name "${DB_NAME}_*.sql.gz" -mtime +7 -delete
```

### 7.8.2 MinIO 备份

MinIO 数据直接存储在 Docker 数据卷中，备份卷即可：

```bash
# 数据卷快照
docker run --rm -v minio_data:/source -v /backup/minio:/dest alpine \
  tar czf /dest/minio_data_$(date +%Y%m%d).tar.gz -C /source .
```

### 7.8.3 恢复

```bash
# 恢复 PostgreSQL
gunzip -c backup_20260716.sql.gz | docker exec -i ai-image-postgres psql -U postgres -d ai_image_db

# 恢复 MinIO
docker run --rm -v /backup/minio:/backup -v minio_data:/data alpine \
  tar xzf /backup/minio_data_20260716.tar.gz -C /data
```

## 7.9 性能与容量估算

### 7.9.1 硬件建议

| 环境 | CPU | 内存 | 磁盘 | 说明 |
|------|-----|------|------|------|
| 开发/演示 | 2 核 | 4 GB | 50 GB | 单机部署 |
| 生产（低负载） | 4 核 | 8 GB | 200 GB | 分离部署 |
| 生产（高负载） | 8 核 | 16 GB | 500 GB+ | 集群部署 |

### 7.9.2 各服务资源占用

| 服务 | CPU | 内存 | 磁盘 |
|------|-----|------|------|
| PostgreSQL | 1 核 | 1-2 GB | 数据量依赖 |
| Redis | 0.5 核 | 256 MB | 持久化少量 |
| MinIO | 1 核 | 512 MB | 图片存储量依赖 |
| Spring Boot | 1-2 核 | 1-2 GB | 日志约 1 GB/周 |
| Nginx | 0.5 核 | 128 MB | 极小 |

### 7.9.3 图片存储估算

| 场景 | 单张大小 | 日活用户 | 人均生成 | 日增长 | 月增长 |
|------|---------|---------|---------|-------|-------|
| 低负载 | 5 MB | 100 | 5 张 | 2.5 GB | 75 GB |
| 中负载 | 5 MB | 500 | 10 张 | 25 GB | 750 GB |
| 高负载 | 5 MB | 2000 | 20 张 | 200 GB | 6 TB |

建议配置 **自动清理策略**：超过 30 天的作品由用户手动确认后可清理，或提供回收站功能。

## 7.10 安全加固

### 7.10.1 网络安全

- 内部组件间通信限制在 Docker 内部网络，不暴露端口到公网
- MinIO Console (9001) 仅限内网访问
- PostgreSQL (5432) 仅限后端容器访问

### 7.10.2 密钥管理

- 所有密钥通过环境变量传入，不硬编码在代码中
- 生产环境使用 Docker Secrets 或 Vault 管理密钥
- API 密钥定期轮换

### 7.10.3 漏洞防护

- Nginx 层限制请求体大小（`client_max_body_size 20M`）
- 后端层校验所有输入参数（`@Valid` 注解）
- 敏感词过滤（防止提示词注入）
- 限流防护（Redis 滑动窗口，10 次/分钟）
