# 1. 系统总体架构

## 1.1 架构总览

本系统采用 **前后端分离的 B/S 架构**，后端基于 **Spring Boot 4.0.1 + Spring AI 0.8.1**，前端采用 **React/Vue** 单页应用，底层依赖 **PostgreSQL 15 + Redis + MinIO** 三件套，AI 绘图能力通过 **火山引擎 Ark SDK** 调用豆包模型。

## 1.3 系统模块划分

### 1.3.1 前端模块 (Frontend)

| 模块 | 页面 | 功能简述 |
|------|------|---------|
| 登录模块 | 登录页 | 账号登录、Token 持久化、未登录拦截 |
| AI 对话模块 | AI 对话页 | 文生文 + 图生文，SSE 流式输出 |
| 绘图模块 | 文生图页 | 正向/反向提示词、参数面板、生成预览 |
| 绘图模块 | 图生图页 | 上传底图、提示词、重绘强度、对比预览 |
| 作品模块 | 我的作品 | 分页列表、筛选（含对话记录）、预览、下载、删除 |
| 管理模块 | 账号管理 | 用户列表、新增、启用/禁用（管理员） |

### 1.3.2 后端模块 (Backend)

| 模块 | 服务类 | 职责 |
|------|--------|------|
| 鉴权服务 | AuthService | 登录校验、Token 签发/验证、退出 |
| AI 对话服务 | ChatService | 文生文 + 图生文，SSE 流式对话 |
| 文生图服务 | T2IService | 调用豆包文生图 API、结果存储 |
| 图生图服务 | I2IService | 底图上传、调用豆包图生图 API |
| 作品服务 | HistoryService | 历史查询、删除、MinIO 签名 URL |
| 用户管理 | UserAdminService | 增删改查用户、状态管理（管理员） |

### 1.3.3 基础设施模块 (Infrastructure)

| 组件 | 职责 |
|------|------|
| PostgreSQL 15 | 用户表 + 生图记录表 + 对话记录表持久化 |
| Redis | 会话 Token 缓存 + 作品列表缓存 + 限流 |
| MinIO | 文生图成品、图生图成品、底图素材文件存储 |
| 豆包 API | 文生图、图生图、敏感词校验等 AI 能力 |

## 1.4 请求流转路径

### 文生图请求流

```
用户操作 → 前端文生图页 → POST /api/t2i/generate (含 Token)
  → 后端 AuthInterceptor (校验 Token)
  → T2IController (参数校验)
  → T2IService (调用豆包文生图 API)
  → 豆包返回图片 URL
  → 后端下载图片 → 上传 MinIO (ai-text-image)
  → 写入 PostgreSQL 生图记录
  → 返回成品 URL + 元数据给前端
  → 前端展示图片
```

### 图生图请求流

```
用户上传底图 → POST /api/i2i/upload → MinIO (ai-source-img)
用户设置参数 → POST /api/i2i/generate
  → 后端校验 → 调用豆包图生图 API (携带底图 URL)
  → 豆包返回新图 → 上传 MinIO (ai-img2img-out)
  → 写入 PostgreSQL 生图记录
  → 返回成品 URL
  → 前端对比展示原图与新图
```

## 1.5 与非功能性需求的对应

| 非功能需求 | 实现策略 |
|-----------|---------|
| 权限隔离 | 所有接口通过 Token 获取当前用户 ID，SQL 查询带 user_id 条件 |
| 图片访问安全 | MinIO 使用预签名 URL（Presigned URL），过期自动失效 |
| 接口容错 | Spring Retry 重试机制、全局异常处理、前端友好提示 |
| 数据持久 | Docker 数据卷挂载，容器销毁数据不丢失 |
| 并发支持 | Redis 限流 + 缓存，防止重复提交 |
