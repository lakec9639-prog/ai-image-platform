## 一、整体业务概述

本系统为 B/S 架构 AI 图像生成平台，分为**前端交互页面**、**后端业务服务**两大模块；
底层依赖 PostgreSQL 存储用户、生图记录元数据，Redis 缓存登录会话、高频查询数据，MinIO 持久化存储用户生成的原图、底图素材；
AI 绘图能力统一调用豆包开放 API，支持文生图、图生图两种主流生成模式，配套完整用户登录、账号管理、历史作品查看全链路功能。

## 二、分项功能详细业务需求

### 1. 功能 1：文本生成图片（对接豆包 AI 绘图能力）

#### 业务描述

用户输入文字描述词，调用豆包 AI 绘图接口生成全新图片，生成结果持久保存并归属当前登录用户。

#### 细分实现点

1. **前端交互能力**
   - 提供文本输入框，支持正向提示词、反向负面提示词分开填写；
   - 可视化参数配置面板：图片尺寸、生成数量、画风（写实 / 二次元 / 插画 / 3D 等）、图片相似度强度；
   - 生成按钮、实时加载动画、生成失败错误弹窗提示；
   - 生成完成后即时预览大图，提供下载、保存至我的作品、重新生成快捷按钮。
2. **后端业务逻辑**
   - 接收前端文本、绘图参数、用户 Token 鉴权；
   - 参数合法性校验（文字长度、尺寸范围、参数合规过滤敏感词）；
   - 封装请求体调用豆包文生图开放接口，统一处理 API 超时、限流、报错；
   - 豆包返回图片二进制流上传至 MinIO 对象存储，生成唯一文件访问地址；
   - 在 PostgreSQL 写入生图记录：用户 ID、生成类型（文生图）、输入提示词、生成参数、图片 MinIO 路径、生成时间、作品状态；
   - Redis 缓存短期生成任务，防止重复高频提交相同绘图请求。
3. **存储规则**
   - MinIO 桶划分：`ai-text-image` 存放所有文生图成品；
   - 数据库记录绑定用户 ID，实现作品归属隔离。

### 2. 功能 2：图片生成图片（对接豆包图生图能力）

#### 业务描述

用户上传本地参考底图，搭配文字提示词，基于原图风格 / 结构重绘生成新图片，生成记录与原图素材统一归档。

#### 细分实现点

1. **前端交互能力**
   - 本地图片上传区域，支持拖拽上传、点击选择文件；限制上传格式（jpg/png/webp）、单图大小上限；
   - 上传原图实时缩略预览，支持裁剪基础操作；
   - 搭配提示词输入框、图片重绘强度滑块（控制原图保留程度）、画风、尺寸参数；
   - 生成过程进度提示，支持取消绘图任务；
   - 生成结果对比展示原图与新图，提供保存、下载、再次图生图复用底图功能。
2. **后端业务逻辑**
   - 校验登录态、上传文件格式 / 大小、图片内容敏感检测；
   - 将用户上传底图先存入 MinIO 临时素材桶，获取素材访问地址；
   - 封装底图地址、提示词、重绘参数调用豆包图生图 API；
   - AI 生成新图上传至 MinIO 成品桶；
   - PostgreSQL 写入完整记录：用户 ID、生成类型（图生图）、原图 MinIO 路径、提示词、重绘强度、成品图路径、生成时间；
   - Redis 缓存临时上传素材，自动清理长期未使用底图。
3. **存储规则**
   - MinIO 分桶：`ai-source-img`（用户上传底图素材）、`ai-img2img-out`（图生图成品）；
   - 素材与成品通过记录 ID 关联，删除作品时同步清理 MinIO 对应文件。

### 3. 功能 3：生图历史记录查看（基于 MinIO 存储 + PostgreSQL 元数据）

#### 业务描述

登录用户可查询自己全部历史生成作品，分页展示、筛选、预览、管理历史图片，图片实体文件全部存储在 MinIO。

#### 细分实现点

1. **前端交互能力**
   - 独立「我的作品」菜单页面；
   - 分页列表展示：作品缩略图、生成时间、生成类型标签（文生图 / 图生图）；
   - 筛选功能：按生成时间区间、绘图类型筛选；
   - 点击缩略图弹窗大图预览，支持下载原图、删除作品、复用提示词重新绘图；
   - 分页加载、无数据空状态提示、加载缓冲动画。
2. **后端业务逻辑**
   - 根据登录用户 ID 查询 PostgreSQL 生图表，分页返回作品元数据；
   - 元数据中携带 MinIO 文件临时访问 URL，前端直链加载图片；
   - 删除作品接口：数据库删除对应记录，同时调用 MinIO 接口删除存储的原图 / 成品文件；
   - Redis 缓存当前用户最近 20 条常用作品，提升列表加载速度；
   - 权限隔离：用户仅可查询、操作自身所属作品，禁止跨用户访问他人历史记录。
3. **存储联动逻辑**
   - 图片实体文件永久存 MinIO，数据库只存元数据与文件路径，不存储二进制图片；
   - 访问图片时后端生成带时效的 MinIO 签名 URL，保障存储资源访问安全。

### 4. 功能 4：账号登录（基于 PostgreSQL 用户表 + Redis 会话缓存）

#### 业务描述

系统提供账号密码登录能力，校验用户身份，签发会话凭证，全局接口鉴权控制访问权限。

#### 细分实现点

1. **前端交互能力**
   - 独立登录页面：账号输入框、密码输入框、登录按钮、错误提示（账号不存在 / 密码错误 / 参数为空）；
   - 记住登录状态复选框，本地持久化会话 Token；
   - 未登录状态拦截：访问我的作品、绘图页面自动跳转登录页；
   - 页面右上角登录用户昵称、退出登录按钮。
2. **后端业务逻辑**
   - PostgreSQL 存储用户账号表：用户 ID、用户名、加密密码、创建时间、账号状态（启用 / 禁用）；
   - 密码使用不可逆加密算法存储，数据库不保存明文密码；
   - 登录接口校验账号密码，校验通过生成唯一 Token；
   - Token、用户基础信息存入 Redis 设置过期时间，作为登录会话缓存；
   - 全局请求拦截器：所有绘图、历史记录、账号管理接口校验请求头 Token，未登录 / 失效 Token 直接拒绝访问；
   - 退出登录接口：清除 Redis 内当前用户会话缓存，强制 Token 失效。

### 5. 功能 5：简单账号管理（基于 PostgreSQL 用户数据表）

#### 业务描述

提供基础用户账号维护能力，仅管理员账号可操作，实现用户新增、查询、启用 / 禁用账号基础运维功能。

#### 细分实现点

1. **前端交互能力**
   - 管理员专属「账号管理」菜单，普通用户隐藏该入口；
   - 用户列表分页表格：展示用户名、创建时间、账号状态；
   - 新增用户弹窗：填写用户名、初始密码；
   - 操作按钮：禁用 / 启用指定用户账号；
   - 账号搜索框：按用户名模糊检索用户；
   - 操作二次确认弹窗，防止误操作。
2. **后端业务逻辑**
   - 接口权限校验：仅管理员角色 Token 允许访问账号管理接口；
   - 新增用户：校验用户名唯一性，密码加密存入 PostgreSQL 用户表，默认账号状态为启用；
   - 用户列表查询：分页、模糊搜索用户名，返回用户基础信息（不返回加密密码）；
   - 账号状态修改接口：更新用户表 status 字段，禁用账号后该用户 Token 立即失效，无法登录系统；
   - 数据约束：不支持删除用户，仅做状态禁用，保留用户历史生图数据归档。
3. **数据库关联约束**
   - 用户表与生图表通过 user\_id 外键关联，即使账号禁用，历史作品数据保留不级联删除。

## 三、底层依赖环境配套说明

1. **PostgreSQL 15**
   - 存储两张核心业务表：用户账号表、生图历史记录表；
   - 持久化所有业务元数据，支持关联查询、分页、权限过滤。
2. **Redis**
   - 缓存用户登录会话 Token；
   - 缓存高频访问的用户作品列表；
   - 限制 AI 绘图接口重复提交、接口限流。
3. **MinIO 对象存储**
   - 分桶存储：文生图成品、图生图成品、用户上传参考底图；
   - 提供图片文件持久化存储、临时签名访问、文件删除能力。
4. **豆包 AI 开放接口**
   - 封装文生图、图生图两套 API，作为系统绘图能力底层支撑。

## 四、非功能性需求补充

1. 权限隔离：用户数据、作品数据严格隔离，不可越权访问；
2. 图片访问安全：MinIO 图片不暴露永久公链，使用时效签名 URL；
3. 接口容错：豆包 AI 接口超时、限流、报错提供友好前端提示；
4. 数据持久：数据库、对象存储均使用 Docker 数据卷持久化，容器销毁数据不丢失；
5. 并发支持：Redis 缓存减轻数据库查询压力，支持多用户同时提交绘图任务。

## 五、系统模块划分

1. 前端模块：登录页、AI 绘图页（文生图 / 图生图）、我的作品历史页、管理员账号管理页；
2. 后端模块：用户登录鉴权服务、AI 绘图对接服务、作品存储与查询服务、管理员账号运维服务；
3. 基础设施模块：PostgreSQL 数据库、Redis 缓存、MinIO 对象存储、豆包 AI 绘图 API。
